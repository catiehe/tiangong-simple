# PRISM LCA — Plan 0908 (real magic-link auth + richer mock dataset)

Follow-up to `plan.md` (2026-09-07), whose entire build order is done and live at
https://catiehe.github.io/tiangong-simple/. This plan covers two specific
follow-ups the user asked for next:

1. Make magic-link sign-in actually work, end to end, not just render a form.
2. Replace the placeholder 1-row-per-type mock dataset with a richer one,
   using naming/content conventions pulled from the real LCA platform this
   app is modeled on.

## Background: what the real repos actually contain

Checked both repos the user pointed at before writing this plan:

- **`linancn/tiangong-lca-next`** — the full production app (UmiJS + Ant
  Design Pro, Electron build, i18n, review workflows). Confirms this is not
  something to copy wholesale — deliberately out of scope, as plan.md already
  decided.
- **`catiehe/database-engine`** — the real Supabase schema source for that
  app. One Postgres table per data type (`processes`, `flows`, `contacts`,
  `flowproperties`, `sources`, `unitgroups`, `lifecyclemodels`), each storing
  a full **ILCD-format document** in a `json jsonb` column, plus workflow
  columns (`version`, `state_code` for draft/review/published, `team_id`,
  `review_id`, a 1536-dim `embedding` vector for semantic search) and 280+
  migrations layering on review queues, worker jobs, hybrid/semantic search,
  portal projections, etc.

That confirms plan.md's original call: we are **not** adopting the ILCD
schema or the per-type-table design. PRISM LCA keeps its single generic
`datasets` table (`type` + flat `payload` jsonb) — what we're borrowing from
these repos is realistic **naming and content conventions** for the mock
rows (ecoinvent/ILCD-style process and flow names, real-looking units and
exchanges), not their schema or complexity.

## 1. Real magic-link auth

**Current state:** `signInWithOtp` is wired in `SignIn.tsx`, Supabase JS's
default `detectSessionInUrl` handles the callback — but nobody has ever
actually clicked a real emailed link, in dev or on the deployed site.

Steps:

- **a. Supabase dashboard config** (user must do this — no CLI/API access to
  it from here): under Auth → URL Configuration, set Site URL to
  `https://catiehe.github.io/tiangong-simple/` and add both that URL and the
  Codespaces forwarded URL (`https://*.app.github.dev`) to Redirect URLs.
  Without this, Supabase silently rejects or mis-redirects the callback.
- **b. Fix a real bug in `SignIn.tsx`:** `emailRedirectTo: window.location.origin`
  resolves to `https://catiehe.github.io` on the deployed site — missing the
  `/tiangong-simple/` base path from `vite.config.ts`'s `base: "./"` — which
  would land the clicked link on a GitHub 404 page instead of the app. Fix:
  `window.location.origin + import.meta.env.BASE_URL`.
- **c. Round-trip it for real:** send a magic link to catiehe@gmail.com from
  the Codespaces dev server, click through, confirm the sidebar footer shows
  signed-in and `/open-data/:type/new` is reachable. Repeat once against the
  deployed GitHub Pages site.
- **d. Stretch, only if (b)/(c) surface it:** GitHub Pages has no
  server-side rewrite, so `BrowserRouter` 404s on a hard refresh or direct
  link to any non-root route (e.g. `/open-data/process`). Standard fix is
  copying `dist/index.html` to `dist/404.html` in the deploy workflow. Not
  required for the auth redirect itself (which targets root), but adjacent
  and cheap to fix while touching auth/deploy.

## 2. Richer mock dataset

**Current state:** `src/mock/datasets.json` / `supabase/seed.sql` have
exactly one made-up row per type (7 rows total, a placeholder "cotton
t-shirt" example), with no cross-references between rows.

**Plan:** ~3-4 rows per type (~20-24 rows total), written in the
naming/content style of real LCA data (ecoinvent/ILCD-style names like
"Electricity, high voltage {CN}| production mix", "Carbon dioxide, fossil",
standard flow properties/unit groups like Mass/kg and Net calorific
value/MJ), with actual cross-references — a process's `exchanges` list flow
names that exist as real rows under `flow`, not made-up strings. Same flat
`payload` jsonb shape as today — no schema change.

Steps:

- **a.** Draft the ~20-24 row mock dataset: 3-4 processes, 4-5 flows they
  reference, 2-3 flow properties, 2 unit groups, 2-3 sources, 2-3 contacts,
  1-2 models tying processes together into a life-cycle chain.
- **b.** Update `src/mock/datasets.json` (keeps the no-backend fallback path
  working exactly as it does today).
- **c.** Update `supabase/seed.sql` to match exactly (same ids/content),
  still idempotent (`on conflict do nothing`) so re-running is safe.
- **d.** Run the updated `seed.sql` against the real Supabase project — no
  `supabase` CLI or service-role key is available in this environment, so
  this has to go through the SQL editor in the dashboard, same as the
  original 7 rows.
- **e.** Reload the deployed GitHub Pages site, click through all 7 sidebar
  sections, confirm the richer, cross-referenced data renders.
